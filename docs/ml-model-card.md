# LIAN on-device models: model card

Generated by `./gradlew :tools:trainer:trainModels` — do not edit by hand. Corpus date: 2026-10-01.

## What they are

Two small logistic-regression classifiers over hashed binary features (`LinearModel`, format LNM1).
They run entirely on the phone, in pure Kotlin, with no ML runtime, no native code and no network.
Weights are 8-bit integers, so the raw score is an exact integer sum: identical on every device.
Each file is listed in the intel SHA-256 manifest and refused at runtime if altered.

| Model | File | Input | Featurizer | Size |
|---|---|---|---|---|
| message | `message.vgm` | the text of a message (English) | `msg-v1` (2^18 buckets) | 256 KB |
| domain | `domain.vgm` | the registrable name of a link's domain | `dom-v1` (2^18 buckets) | 256 KB |

## How they are used

- **They add evidence; they never decide alone.** A model hit is one finding (`msg.ml.pattern`, `link.ml.domain`) in the
  same noisy-OR score as the hand-written rules. On its own a model can raise a result to *Be careful*; reaching
  *Likely a scam* or *Dangerous* needs a deterministic rule as well.
- **Every hit is explained.** The finding lists the words, domain parts or signals that contributed most.
- **Official brand domains are never scored** by the domain model.

Messages labelled spam or smishing are positives. Exact duplicates across the two datasets are merged and texts
labelled both ways are dropped. Domains are reduced to their registrable label with the Public Suffix List;
phishing hosts on popular (Majestic-listed) domains are skipped as compromised rather than deceptive.
Samples are split 80/10/10 (train/validation/test) by a hash of the normalised text.

Thresholds were chosen on the validation split: *high* at ≥ 98 % (messages) and
≥ 97 % (domains) validation precision, *medium* at ≥ 90 %.
Precision depends on how common scams are in what is checked; these figures are at the corpus ratio.

## Limitations

- **English only.** Messages in other languages get no model score (rules still apply).
- **Dated public data.** The SMS datasets are from 2011–2022; recent formats are covered only by a small set of
  hand-written examples. Expect lower recall on new scam styles.
- **Names, not intent.** The domain model judges how a name looks. A phishing page on a hacked, ordinary-looking
  site scores low; a legitimate site with a random-looking name may score high (hence *Be careful*, not more).
- **No learning on the phone.** Models change only through a signed app update; nothing about what you check is
  kept or used for training.

## Training procedure

AdaGrad logistic regression, 6 epochs, learning rate 0.2, balanced class weights, L2 chosen from {1e-6, 1e-5, 1e-4}
on validation log-loss; deterministic SplitMix64 shuffle; 8-bit quantisation with the scale chosen on validation;
the encoded file is re-decoded and re-scored against the trainer before it is written.

- `message.vgm`: L2 1.0E-6, 5106 training samples, thresholds (logit) medium -1.3266, high 1.4369.

- `domain.vgm`: L2 1.0E-4, 937514 training samples, thresholds (logit) medium 2.3282, high 3.9319.
